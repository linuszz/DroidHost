# DroidHost 0.1.1

**Built-in Linux distributions, a desktop per machine, installs that survive a restart — and a quieter, general-purpose launcher.**
Install it over 0.1.0 — same signing key, your machines and settings stay.

This release builds out the virtual-machine side of DroidHost: install a built-in distribution as a
machine of its own, import your own system (now including pacman-based Arch Linux ARM), and manage
each machine through a lifecycle that persists across restarts. The launcher leans further into
general Linux/desktop use: the game launcher services are gone, and the optional shared runtime no
longer nags.

> **Early software.** The runtime and desktop are inherited from DroidDeck and have been run on
> real hardware there. The pacman import path has been run on real hardware in DroidHost (an
> Arch Linux ARM guest with a KDE desktop on Adreno). The built-in distribution and per-machine
> paths are wired and build-verified; where something has not been tested on hardware, treat it
> as untested.

---

## Built-in distributions: Debian 13 and Ubuntu 26.04

DroidHost packages two ARM64 Linux distributions you can install as a machine of its own:

- **Debian 13 (trixie)**
- **Ubuntu 26.04**

Each is downloaded from DroidHost's own components channel and installed per machine. The shared
runtime is now an optional component for the agent harness and legacy machines — virtual machines
do not depend on it.

## A desktop per machine

Each virtual machine installs and carries its own desktop environment and bundled apps, rather than
sharing one. Removing a machine removes its desktop and apps; the system image, settings and shared
libraries stay.

## Importing your own distribution — honest acceleration

When you import a root filesystem, DroidHost reads it and reports GPU acceleration only when it can
actually deliver a driver for that system. A driver reaches an imported system only when it matches
the built-in runtime's distribution and release, because the import reuses that runtime's driver
repository. Anything else falls back to software rendering, and the import dialog says so plainly
instead of promising a GPU it cannot provide.

## Arch Linux ARM guests

Pacman-based guests are now supported imports: the probe reads Arch Linux ARM's flat GPU stack,
guest preparation masks hooks that want an init system, and the desktop install syncs with a full
`pacman -Syu`, populates the keyring and installs the Arch names of the KDE seed list. Imported
machines also receive the bundled desktop configuration and helpers, re-seeded before every session
so existing machines heal on update. Large hard-linked archives unpack correctly.

A note on names: on ARM64 devices this is **Arch Linux ARM** (archlinuxarm.org) — the community
aarch64 port with its own keyring and repositories, not the official x86_64 Arch. Expect AUR
packages to need source builds or to be unavailable on aarch64. A one-tap built-in Arch Linux ARM
preset is in the works; this release supports importing one.

## Installs that survive a restart

Each machine keeps a persisted lifecycle: pause, resume, retry and cancel survive an app restart,
partial downloads are kept so a resume continues instead of starting over, and a failed stage says
why it failed. Installs interrupted by a restart are recovered on launch. Delete is decoupled from
the install: it cancels the machine's own job, waits for it to end, then removes the machine with
its rootfs, desktop and partial downloads — even mid-install, and even for a machine that never got
a rootfs.

## A quieter, general-purpose launcher

- The GOG, Ubisoft and Rockstar launcher services are no longer built or shipped. Steam is
  unaffected. Upstream code is kept for future merges; the three stores are disabled at the build,
  registration and UI layers.
- The shared Linux runtime is optional: an uninstalled runtime no longer lights the setup badge,
  and VM wording says "use" instead of "play".
- The setup badge now only flags real blockers — the phantom process limit and Syncthing. An
  available update for the optional shared runtime stays visible on the setup page, with its
  Update button, without badging the tab.

## Fixes

- Deleting a machine without a rootfs no longer falls into the desktop-removal path; it deletes
  the machine.
- The setup tab no longer badges when an installed runtime lacks a version marker.

## Also in this release

- Build and release plumbing for the built-in distribution runtimes: revision-tagged releases,
  retry on transient fetch failures, and quieter CI for runtime-only changes.
