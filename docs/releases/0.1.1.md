# DroidHost 0.1.1

**Built-in Linux distributions, a desktop per machine, and an honest word about acceleration.**
Install it over 0.1.0 — same key, same shared runtime, nothing to re-download.

This release builds out the virtual-machine side of DroidHost: you can install a built-in
distribution as a machine of its own, each machine carries its own desktop, and importing your own
system tells you the truth about whether it gets GPU acceleration.

> **Early software.** The runtime and desktop are inherited from DroidDeck and have been run on
> real hardware there. The built-in distribution and per-machine paths below are wired and
> build-verified in DroidHost, but not yet re-verified end-to-end on every device. Where something
> has not been tested on hardware, treat it as untested.

---

## Built-in distributions: Debian 13 and Ubuntu 26.04

DroidHost now packages two ARM64 Linux distributions you can install as a machine of its own:

- **Debian 13 (trixie)**
- **Ubuntu 26.04**

Each is downloaded from DroidHost's own components channel and installed per machine. The shared
runtime the desktop session uses is unchanged.

## A desktop per machine

Each virtual machine installs and carries its own desktop environment and bundled apps, rather than
sharing one. Removing a machine removes its desktop and apps; the system image, settings and shared
libraries stay.

## Importing your own distribution — honest acceleration

When you import a root filesystem, DroidHost reads it and reports GPU acceleration only when it can
actually deliver a driver for that system. A driver reaches an imported system only when it matches
the built-in runtime's distribution and release, because the import reuses that runtime's driver
repository. Anything else — Debian, other Ubuntu releases, and other distributions — falls back to
software rendering, and the import dialog says so plainly instead of promising a GPU it cannot
provide.

## Also in this release

- Clearer machine states and removal semantics.
- Build and release plumbing for the built-in distribution runtimes: revision-tagged releases,
  retry on transient fetch failures, and quieter CI for runtime-only changes.
