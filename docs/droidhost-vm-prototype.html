删除这台虚拟机？

将删除 Debian 13 的 rootfs、已安装的桌面与全部用户数据。 此操作不可撤销。
与删除桌面不同　删除桌面只卸载 Plasma，系统镜像保留；删除虚拟机会连发行版一起清除。

设计要点

  • 「新建虚拟机」放在桌面 tab 内，不新增导航项——VM 与桌面同属「运行环境」，拆开会让用户多绕一层。
  • 两条来源，同一条后续流程：预置发行版与用户导入最终都走「探测 → 落盘 → 驱动 → 桌面」。
  • 探测结果前置。在装之前就告诉用户「会用 GPU 加速」或「将以软件渲染运行」，而不是装完才发现。
  • 降级是显式的。L1 失败自动转 L2，并在安装过程中显示降级原因。
  • 删除语义分离：「删除桌面」保留系统镜像；「删除虚拟机」连发行版一起清除。文案必须区分。
  • 内核边界写在界面上。导入的是用户态，内核由 Android 提供——这是 proot 架构的硬限制，必须提前告知。

落地顺序

  • P1 多 rootfs 布局　files/vms/<id>/rootfs + rootDir(vmId) + VmStore 多实例。不改用户可见行为，可独立验证。
  • P2 导入向导　文件选择 + rootfs tarball 解包 + 探测。
  • P3 L1 驱动包　Ubuntu 已有管线，扩到 Debian。
  • P4 L2 配置注入　兜底路径，保证「装得上、跑得动」。
  • P5 桌面包按 VM 独立装卸　复用 desktop-pack.py 的清单机制。
